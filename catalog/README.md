# catalog/ — 문헌 정본과 다운로드 배포

`catalog/<id>.json`이 배포 문헌의 정본이다. 사용자는 앱의 **문헌 받기**에서 설치하거나 업데이트하며, 설치한 문헌과 개인 수정은 사용자 저장 공간에 보관된다. `src/data/`에 문헌 사본을 추가하지 않는다.

## 저작부터 출시까지

1. 해당 GitHub 이슈의 범위와 완료 조건을 확인하고 작업 브랜치를 만든다.
2. 앱에서 문헌을 저작·수정한 뒤 문헌 JSON을 내보낸다. 출처·이용 근거와 내용·독음도 확인한다.
3. 저장소 루트에서 `node scripts/promote.mjs <내보낸-문헌.json>`을 실행한다. 문헌을 검사한 뒤 사용자 전용 정보(`source`, `schemaVersion`, `updatedAt`, 카드의 `editedAt`·`status`)를 제외하고 `catalog/<id>.json`에 기록한다. 새 문헌의 개정 번호는 1, 기존 문헌은 기존 번호 + 1이며 기존 `order`는 유지한다.
4. 변경 내용을 검토하고 `npm run lint`, `npm test`, `npm run build`를 실행한다. 새 한자로 폰트 경고가 생기면 아래 폰트 절차도 따른다.
5. [PROCESS.md](../PROCESS.md)에 따라 출시 PR의 앱 버전을 정하고 `Related #번호`로 연결한다. 별도 리뷰와 필수 CI를 통과해 `main`에 병합하면 배포된다. 문헌 설치·업데이트와 표시를 확인하고 Release·검증 근거를 이슈에 남긴 뒤 완료한다.

`promote`는 실행할 때마다 기존 문헌의 개정 번호를 올린다. 반복 실행 후에는 최종 변경과 개정 번호를 함께 확인한다. 이 스크립트는 앱 버전을 올리거나 PR·배포를 수행하지 않는다.

## 데이터와 버전

- `id`: 파일명과 일치해야 한다. 배포한 문헌 ID와 기존 카드 ID는 보존한다. ID가 바뀌면 설치자의 학습기록과 업데이트 연결에 영향을 준다.
- `version`: 문헌 개정 번호인 1 이상의 정수다(생략된 기존 데이터는 1로 취급). 기존 문헌 내용이 바뀌면 올려 설치자에게 업데이트를 알린다. 앱의 `package.json` 버전과 별개다.
- 앱 버전: 새 문헌 추가는 MINOR, 기존 문헌 수정은 PATCH가 기본이며 다른 변경과 함께 출시하면 [PROCESS.md](../PROCESS.md)의 기준을 따른다.
- `order`: 카탈로그 목록에서 작은 값부터 정렬한다. 없으면 뒤로 보내고, 동률은 문헌 ID 순으로 정렬한다.
- `_collections.json`: 선반 초기값과 참고문헌 관계를 담는 메타데이터다. 다운로드 문헌 목록에서는 제외되고 앱에서 참조한다. 사용자 선반에는 최초 시드로 적용된다.

## 빌드와 검사 대상

[vite.config.mts](../vite.config.mts)의 `build-catalog` 플러그인이 `_`로 시작하지 않는 문헌 JSON을 `dist/catalog/`로 복사하고 `index.json`을 생성한다. 목록에는 문헌 ID·제목·부제·표지색·개정 번호·카드 수가 들어간다. `dist/`는 산출물이므로 직접 편집하지 않는다.

카탈로그 전체를 학습용으로 자동 설치하지는 않는다. 다만 [src/docs.ts](../src/docs.ts)는 구 버전 데이터 이전을 위한 8문헌과 오프라인 스타터 설치에 사용할 문헌을 카탈로그 정본에서 번들로 가져온다. 다운로드 배포와 이 번들 용도는 함께 존재한다.

`npm run lint`는 `catalog/*.json`의 카드 ID·연결·문법 범위, 문헌 파일명과 ID, 개정 번호, `_collections.json` 참조와 폰트 커버리지를 검사한다. 경고에는 중복 텍스트·드릴다운 매칭·독음 정렬 문제가 포함된다. 자동 검사 통과만으로 내용 완성도나 정확성이 보장되지는 않는다.

## 폰트 갱신

WenKai 서브셋은 **카탈로그 전체**의 각 레벨 카드 `text`, 문헌 `title`·`sub`, 워드마크 `文讀`의 한자를 대상으로 생성한다.

- 새 글자가 서브셋에 없다는 lint 경고가 나오면 `npm run font:subset`을 실행한 뒤 다시 lint와 화면 표시를 확인한다.
- 생성한 `public/fonts/wenkai-tc-sub.woff2`, `.chars.txt`, 필요 시 `.missing.txt` 변경을 같은 제품 PR에 포함한다.
- 원본 WenKai 자체가 지원하지 않는 글자는 재생성으로 해결되지 않는다. `.missing.txt`에 기록되며 명조 폴백으로 표시되므로 실제 표시를 확인한다.
