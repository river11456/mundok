# 문장 블록 학습 목업

[Related #28](https://github.com/river11456/mundok/issues/28). 실제 문독의 라이브러리, 글꼴, 문장 학습·독음·해석 편집을 재사용하는 로컬 디자인 검토용 화면이다. 운영 앱의 진입점과 배포 산출물에는 포함하지 않는다.

## 실행

저장소에서 `npm install` 이후 `npm run dev -- --host 127.0.0.1 --port 4178 --strictPort`를 실행하고 <http://127.0.0.1:4178/design/prototypes/sentence-blocks/>를 연다. 기존 개발 서버와 다른 포트를 사용한다. 목업은 루프백 주소에서만 시작하며, 목업 표시 없이 기존 문독 저장 키가 발견되면 초기화를 중단한다.

대의정성·상고천진론·사기조신대론의 샘플 사본을 해당 주소의 브라우저 저장소에 저장한다. 운영 데이터와 동기화하지 않는다. 같은 주소를 다시 열면 편집 내용을 유지한다.

## 체험 순서

1. 본문의 일부를 드래그하고 **문장으로 지정**을 누른다. 앞뒤 나머지 본문은 별도 블록으로 남는다.
2. 연속된 블록의 체크박스를 선택하고 **합치기**를 누른다.
3. 블록 왼쪽 손잡이를 끌어 순서를 바꾼다. 손잡이의 위·아래 방향키도 지원한다.
4. 블록 사이 **＋**로 교수님이 추가한 문장을 넣는다.
5. 본문 또는 **문장 열기**를 눌러 기존 문장 화면으로 이동하고, 연필 버튼으로 음·해석·메모를 작성한다.
6. 상단 문헌 이름으로 본문에 돌아온다. **문장 복습**은 정답을 가린 순차 복습을 시작한다.

블록 변경은 **실행 취소** 또는 ⌘/Ctrl+Z로 되돌린다. 실행 취소 기록은 새로고침 시 사라진다. 문장 편집 후에는 그 편집을 덮어쓰지 않도록 이전 블록 변경 기록을 종료한다. 분할하면 각 원래 문장의 해석·메모는 맨 앞 조각에 남고 나머지는 빈칸으로 시작한다. 합치면 현재 순서대로 해석·메모를 이어 붙인다. 독음·문법·해석 순서는 해당 글자를 따라가며 경계에 걸친 범위는 각 조각에 맞게 나눈다.

## 검증

- `node --experimental-strip-types --test design/prototypes/sentence-blocks/model.test.mjs`: 18개 통과. 한자 확장 문자, 한글 토, 공백과 원문 보존, 기존 주석 보존, 읽기 불일치, 연속 선택, 이동·추가 경계를 확인한다.
- `./node_modules/.bin/tsc --noEmit -p design/prototypes/sentence-blocks/tsconfig.json`: 통과.
- 저장소 `npm run lint`, `npm test`(317개), `npm run build`: 통과. 기존 문헌 연결·폰트 경고는 남아 있다.
- 데스크톱 브라우저에서 드래그 지정/분할, 합치기, 실행 취소, 손잡이 이동, 사이에 추가, 기존 편집기에서 독음·해석 저장, 새로고침 유지, 방향키 이동, 라이브러리 메뉴를 연 뒤 문헌 진입을 직접 확인했다.
- 별도 리뷰에서 발견한 온보딩 초기화 누락, 라이브러리 메뉴 잔류, 기존 생성·삭제 후 내비게이션 연결을 수정했다. 재검토 결과 남은 지적 없음.

모바일 실기기, 운영 PWA/오프라인 배포, 실제 사용자 데이터 이전, 저장 용량 초과 및 새 문헌 생성·마지막 문장 삭제의 브라우저 회귀는 미검증이다. 이 목업은 Anki 제품 코드 삭제나 저장 형식 변경을 수행하지 않는다.

출시 경로 검사는 이 목업의 실행 파일 6개만 문서용으로 분류한다. 미등록 파일이나 제품 파일이 함께 바뀌면 기존 출시 검사를 계속 적용하며 별도 회귀 테스트로 확인한다.

## 시각 방향 재검토

사용자 승인 방향: 기존 문독의 회색 배경·흰색 표면·파란 강조색과 WenKai 한자 서체를 유지한다. 별도 사이드바 없이 기존 서재와 공용 뒤로가기·홈 버튼을 재사용한다. Bear와 Craft에서는 읽기 편한 간격과 필요한 순간 나타나는 블록 도구만 참고한다. 반복 번호·해석 상태·문장별 카드 테두리는 제거하고 체크박스·손잡이·중간 삽입·문장 열기는 hover/focus 때 드러낸다. 터치 환경에서는 도구를 노출하며 상단 본문 추가 버튼은 항상 제공한다.

통일성 복원 후 검증: 서재→본문→기존 문장 화면→본문 복귀, 드래그 지정/분할과 실행 취소, 상단 추가 대화상자를 브라우저에서 확인했다. 390px 너비에서 가로 넘침이 없음을 확인했다(실기기 터치 검증은 아님). lint·317개 테스트·build·목업 타입 검사 통과. 독립 코드 리뷰 승인, 잔여 지적 없음. 모델·저장 동작 변경은 없다.

## 필기 보존과 표시

본문과 기존 문장 화면에 별도의 필기 목록·상속 표시·원문 팝업을 넣지 않는다. 분할 시 해석·메모는 원래 문장의 첫 글자를 포함하는 조각 한 곳에 남는다. 중간 범위를 선택해 세 조각으로 나눠도 맨 앞 조각이 필기를 갖는다. 여러 문장에 걸친 선택에서는 각 원래 문장의 첫 조각에 필기가 남고, 합쳐지는 조각의 필기는 순서대로 연결한다. 이동은 필기를 그대로 유지한다.

이전 목업에서 나뉜 형제 블록에 공유되던 해석·메모는 처음 실행할 때 앞 블록에 한 번만 옮긴다. 현재 사용자가 쓴 필기를 덮어쓰지 않으며, 참조 원본은 내부 보관하되 화면에 자동 표시하지 않는다. 새로고침이나 재분할로 뒤 문장의 빈칸을 다시 채우지 않는다. 텍스트형 ‘분리 전 참고’ 메모는 자동 재해석하지 않는다. 운영 저장 형식이나 데이터는 변경하지 않는다.

본문 변경으로 위치가 불확실해진 문법은 내부 원본 참조에 보관하며 자동으로 잘못된 글자에 붙이지 않는다. 내부 원본 참조를 재연결하는 전용 UI는 이번 목업 범위 밖이다.

최종 규칙 검증: 모델 18개·전체 317개 테스트, lint/build/타입 검사와 독립 리뷰 통과. 브라우저에서 기존 필기 이전, 앞/뒤 문장 편집값, 추가 분할·실행 취소·새로고침 및 표시/팝업 제거를 확인했다.
