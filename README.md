# 文讀 (문독)

사용자가 한의학 한문의 해석을 직접 작성하고 복습하는 웹앱

---

## 사용 방법 (일반 사용자)

설치할 것이 없습니다. 아래 주소를 브라우저에서 열기만 하면 됩니다.

> **[문독 열기](https://river11456.github.io/mundok/)**

휴대폰·태블릿·PC 화면에 맞춘 UI를 제공합니다. 홈 화면에 추가해 앱처럼 사용할 수 있습니다. 기기별 업데이트·오프라인·복원 확인은 [검증 작업 #5](https://github.com/river11456/mundok/issues/5)에서 관리합니다.

### 내가 추가·수정한 카드는 어디 저장되나요?

학습 진도와 직접 추가·수정한 카드는 **그 브라우저 안에** 저장됩니다. 따라서:

- 다른 기기·다른 브라우저로 접속하면 보이지 않습니다.
- 브라우저의 사이트 데이터를 지우면 저장 내용도 사라집니다. 별도의 서버 백업은 없습니다.

소중한 내용은 화면 **왼쪽 아래 ⤓ 버튼 → "내 데이터 내보내기"** 로 백업해 두세요.
기기를 바꿀 때는 같은 메뉴의 "백업 파일에서 가져오기"로 복원합니다. 현재 브라우저 데이터를 백업 내용으로 덮어쓰므로 가져오기 전에도 백업하고, 다른 문독 탭과 앱 창은 모두 닫아 주세요. 특히 구버전 창은 새 저장 잠금에 참여하지 않습니다.

3.0.0 수정본은 입력을 검사한 뒤 원본의 복구 사본을 브라우저에 저장하고 복원합니다. 복구 사본을 담을 공간이 부족하면 기존 데이터를 바꾸기 전에 중단합니다. 저장 오류 화면이 나오면 **복구 사본 내보내기**로 별도 파일을 보관하고 공간·권한을 확인한 뒤 **다시 시도**하세요. 사이트 데이터를 지우지 마세요. 지원 형식과 호환 제한은 [복구 안내](docs/recovery.md)를 참고하세요. 출시 여부는 [최신 Release](https://github.com/river11456/mundok/releases/latest)에서 확인합니다.

3.0.0 수정본은 같은 주소의 문독 창 하나만 편집할 수 있습니다. HTTPS 또는 localhost에서 Web Locks를 지원하는 브라우저가 필요하며, 잠금 미지원·권한 거부·다른 창 사용 중에는 시작을 중단합니다. 다른 문독 창을 닫고 다시 시도하세요.

> 문헌은 홈 오른쪽의 **추가** 메뉴에서 카탈로그로 내려받거나 직접 만들 수 있습니다. 받은 문헌도 자유롭게 고칠 수 있고, 업데이트가 오면 직접 수정한 카드는 보존됩니다.
>
> 홈에서는 탭이 달린 폴더 모양 타일을 열어 문헌을 정리할 수 있습니다. 새 폴더도 같은 **추가** 메뉴에서 만들며, 현재 생성 UI에는 루트 아래 2단계 제한이 남아 있습니다. 더 깊은 중첩 목표는 [작업 #4](https://github.com/river11456/mundok/issues/4)에서 다룹니다. 폴더 안에서 만든 문헌은 그 폴더에 자동으로 들어갑니다. 폴더를 삭제해도 담긴 문헌과 하위 폴더는 상위 위치로 이동해 보존됩니다.

## 콘텐츠 저작·승격 (관리자)

v2부터 별도 저작 모드가 없습니다 — 관리자도 앱에서는 일반 사용자와 똑같이 저작합니다 (`SPEC.md` 공리 4).

1. **저작**: 앱(배포본 또는 `npm run dev`)에서 문헌을 만들고 카드·문법·해석 순서를 다듬는다.
2. **내보내기**: 문헌 상세 오버레이 → **내보내기** — `<문헌id>.json` 다운로드.
3. **승격**: `node scripts/promote.mjs <내보낸.json>` — 유저 전용 필드 정리 + version 증가 + lint 검사 후 `catalog/<id>.json` 배치.
4. **검토·배포**: 관련 GitHub 이슈에서 작업 범위 확인 → 작업 브랜치에서 문헌 개정 번호·앱 버전 반영 → 검사·PR 검토 → `main` 병합 → 배포 확인. 자세한 절차는 [PROCESS.md](PROCESS.md)를 따른다.

> **폰트**: 새 문헌에 새 한자가 들어오면 lint가 WARN을 낸다 → `npm run font:subset` 재실행 후 산출물 커밋.
> **원본 PDF**: 문헌 원본 PDF는 git에서 분리해 관리자 로컬 `~/Documents/문독-원본PDF/`에 보관 (2026-07-08).

## 배포 구조 (개발자 참고)

- **호스팅**: GitHub Pages — 제품 변경 PR이 `main`에 병합되면 검사·배포하고, 운영 파일 확인 후 GitHub Release를 기록한다. 문서·테스트·관리 도구만 바뀌면 제품 배포를 생략한다.
- **콘텐츠 정본**: `catalog/*.json` → 빌드 시 `dist/catalog/`(+`index.json`) 정적 배포. 초기 컬렉션·참고문헌 관계는 `catalog/_collections.json`
- **유저 공간**: 브라우저 `localStorage` `mundok-v3/*` — 문헌(`docs`)·폴더 트리(`collections`)·리뷰 로그(`log/<docId>`)·세션·설정. 문헌은 출처(직접 생성/카탈로그) 무관 동등
- **저장 추상화**: `src/storage/` — 현재 `LocalStore`와 문헌·폴더 저장 코드가 브라우저 데이터 저장을 담당합니다.
  계정·자동 동기화·서버 저장은 아직 없습니다. 도입하려면 인증·충돌 해결·데이터 이전을 함께 설계해야 합니다.
- **개발 환경**: Node.js 22.18 이상(22 계열), 처음에는 `npm ci`로 개발 의존성을 설치합니다.
- **개발**: `npm run dev` (vite) / 테스트 `npm test` / 빌드 `npm run build` (데이터 lint → tsc → vite)
